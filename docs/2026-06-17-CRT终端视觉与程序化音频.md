# 2026-06-17 CRT终端视觉与程序化音频

## 本轮需求
- 基于现有 Phaser 4 游戏做一轮整体视觉改造，方向为老式 CRT、机场航显、琥珀终端、低保真设备。
- 新增不依赖外部素材的程序化音频系统 `src/audio/TerminalAudio.js`，使用 Web Audio API 生成短促反馈音和低音量 hum。
- 将 hover、确认、错误、刷新、场景切换、屏幕开关、游戏结束等交互绑定到终端音频。

## 设计方案
- 新增统一主题 `CRT_THEME`，集中管理琥珀色板、字体、FX 和音频默认配置。
- 新增 `CrtScreen`，以安全 overlay 为主实现 scanline、dot mask、noise、vignette、glitch、pulse，并在可用时尝试启用 Phaser 4 camera filters。
- 新增 `TerminalFactory`，先提供 label、panel、button、table、ticker、statusLight 等轻量终端 UI 构件。
- 新增 `StyleTestScene` 作为完整视觉样机，不污染核心玩法入口。
- 真实游戏保留现有玩法结构，只替换配色、卡面读数、HUD 文案、弹层样式和关键反馈。

## 实现要点
- `TerminalAudio` 优先复用 `scene.sound.context`，浏览器音频未 unlock 时延迟到 pointerdown/keydown 或 Phaser unlocked 事件后初始化。
- 音效全部由 oscillator、gain、filter、noise buffer、waveshaper 生成，包括 hum、hover tick、confirm 双音、error 下滑、rowRefresh 随机短 tick、glitch 噪声等。
- 菜单改为终端启动屏，提供 `> INIT RUN` 和 `> STYLE TEST`。
- 主 HUD 改为 `UNIT STATUS`、`DECK SIGNAL`、`GATE GRID B-03`、`CARGO BUFFER` 等终端语言。
- 卡牌读数从 emoji 改为 `HP/AT/AR`，颜色改为克制琥珀/暗橙体系。
- SelectionOverlay 和 LevelManager 的三选一、商店、房间选择接入 hover/confirm/error/rowRefresh。

## 遇到的问题及解决
- 构建时发现 `src/systems/HelpCardEffects.js` 尾部 `showFloatText` 缺失函数声明，导致 Vite import analysis 解析失败。已补回函数声明，并顺手统一飘字为终端色。
- 浏览器截图 API 在当前环境下超时，但已通过本地 Vite、canvas 状态、控制台日志、菜单到 StyleTest 再到 GameScene 的交互路径验证运行无错误。
